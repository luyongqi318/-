## 四、部署到常驻环境（三选一）

### Docker Compose（自有服务器）

```bash
docker compose up -d --build
# http://localhost:3000，数据挂载 ./data
```

### Railway

```bash
npm i -g @railway/cli && railway login && railway init && railway up
```

部署后挂 Volume 到 `/app/data`，配置环境变量 `DEEPSEEK_API_KEY`、`HR_USER`、`HR_PASS`、`AUTH_SECRET`；健康检查用 `/api/health`。

### Render

推送到 GitHub 后，Render → New → Blueprint 导入 `render.yaml`（磁盘已配好 `/app/data`）。

## 五、运维手册

- **数据位置**：`data/hr.db`（容器内 `/app/data/hr.db`）。备份用「系统设置 → 数据备份」，恢复时停服务替换该文件再启动。
- **版本更新**：`npm run build`（不影响线上）→ 停服务 → `npm run release` → `npm run serve`，中断约 3–5 秒。
- **重置演示数据**：删除整个 `data/` 目录后重启，会自动重新建表并写入演示数据。
- **忘记密码**：删除数据库 `settings` 表里 `admin_password_hash` 这条记录后重启，恢复默认密码。
- **限流**：登录 10 次 / 5 分钟，智能体 20 次 / 分钟，均为进程内限流（单实例足够）。
- **安全**：所有页面与写接口校验会话；密码用 scrypt 哈希；模型 Key 只存服务器本地且不下发浏览器。

## 六、还需要酒店方提供

1. **DeepSeek（或任意 OpenAI 兼容）API Key**
   登录后在「系统设置」粘贴保存即可，无需重启；也可在 `.env.local` 配 `DEEPSEEK_API_KEY`。
   拿到后智能体从「本地演示模式」切换为真实大模型对话。

2. **持久化托管凭据**：Railway Token，或一个 GitHub 仓库（走 Render Blueprint）。
   没有它，公网访问依赖当前这台机器与临时隧道；有了它即可常驻、独立域名、关机不受影响。
